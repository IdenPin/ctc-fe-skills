# Structure Reference

## 目录职责深度定义

### app

放应用级基础设施，不允许混入任何具体业务代码：

- router 实例和全局路由装配、全局路由守卫
- 全局状态（Pinia/Redux）实例初始化以及全局通用 store（如 `auth`、`theme`、`locale`、`layout`）
- 全局插件注册、引导启动逻辑 (`bootstrap.ts`)

### features

业务域闭环目录。适合长期演进的大型项目。一个业务域应该能够独立被理解、修改和迁移。

### shared

跨模块共享能力必须按语义分区，禁止把所有公共代码堆进一个 `components/` 或 `utils/`：

- `shared/ui`：Button、Input、Dialog、ValueTag 等不理解用户、订单、字典等业务概念的基础 UI。
- `shared/lib`：`useDebounce`、storage、tree 等无业务语义的 hooks 和工具。
- `shared/styles`：全局主题、Reset 和设计 Token。
- `shared/biz`：理解公司稳定业务概念、被多个独立模块长期复用的公共能力，例如用户选择和平台字典展示。

`shared/biz` 不是第二个全局大仓库。能力进入该目录必须同时满足：

1. 被多个独立业务模块长期使用，或明确属于平台级公共业务能力。
2. 对外 API 和核心交互已相对稳定，有明确维护方。
3. 不依赖 `features`、`views`、页面路由或某个模块的私有状态。
4. 不承载审批、订单、营销等具体页面流程；调用方特有规则由调用方包装。
5. 通过业务子域根目录的 `index.ts` 精确暴露公共 API。

```text
src/shared/
├── ui/
│   ├── Select/
│   └── ValueTag/
├── lib/
└── biz/
    ├── user/
    │   ├── UserSelector.vue
    │   ├── types.ts
    │   └── index.ts
    └── dictionary/
        ├── DictTag.vue
        ├── types.ts
        └── index.ts
```

例如订单审批只能选择本部门人员时，限制条件和包装组件应留在订单模块：

```text
features/order/components/ApproverSelector.vue
                         ↓
shared/biz/user/UserSelector.vue
                         ↓
shared/ui/Select.vue
```

若组件只负责根据传入的 `value + options` 显示文本和颜色，它没有字典业务语义，应命名为 `ValueTag` 并放入 `shared/ui`；只有读取公司字典编码、缓存或接口的组件才放入 `shared/biz/dictionary`。

### services

网络请求与外部服务基础设施。

- 放：request client（Axios/Fetch 实例）、Token 刷新拦截器、WebSocket/SSE 核心客户端。
- **绝对不允许放置具体业务接口定义。**

## 业务子模块治理

普通页面的根目录模板不能无限扩展成复杂业务域。模块出现多个业务变体或独立流程时，先按业务职责建立子域，再在子域内部按需使用技术目录。团队规范记录通用约束和判断条件；具体项目的文件清单、迁移映射及实施步骤留在该项目中。

### 1. 目录容量：目标 8 个，硬上限 10 个

统一统计**单个目录直接包含的手写源码文件**：组件、脚本、样式、Mock 和测试均计入；子目录、Markdown、图片字体及明确生成文件不计。扫描器支持的扩展名和排除方式见下文。规则覆盖业务模块根目录及其全部子目录，包括 `components/`、`composables/`、`hooks/`、`utils/`、`core/`。

| 同级源码文件数 | 必须采取的动作 |
| --- | --- |
| 1～8 | 按现有职责组织；已有独立变体或子流程仍需归拢，不等数量超限。 |
| 9～10 | 新增前复查业务归属，优先归入已有子域；若保留，说明为何仍属同一职责。 |
| 超过 10 | 目录超限。新增第 11 个前先整理本次所属实体或流程；不能继续在该目录追加源码。 |

这是团队的目录容量约束。不得通过挪到另一个技术目录、按字母分组或创建 `part1/`、`part2/` 绕过。目录模板仅示意位置，不预建空的 API、store、composable、组件或配置文件。

### 2. 业务变体按归属共置

当多个变体分别有视图、状态逻辑、配置或专属类型时，必须为各变体建目录。禁止在同一目录交错平铺多组视图与逻辑；也禁止将它们分别堆入模块顶层的 `components/` 和 `composables/`。

以下只示意归属关系，`variant-a`、`variant-b` 是占位符，落地时替换为实际业务名；文件按需创建：

```text
<business-domain>/
├── index.vue                  # 入口与装配
├── components/                # 多个变体实际共用的展示组件
├── variant-a/
│   ├── VariantA.vue
│   ├── useVariantA.ts
│   └── types.ts
└── variant-b/
    ├── VariantB.vue
    └── useVariantB.ts
```

修改单一变体时，应能在其目录内找到视图和专属逻辑。只用于某一变体的格式化、类型与常量留在该变体内；被多个变体实际共用的能力再提升到最近共同边界。确有 JSX 渲染需求时可以使用 `.tsx`，不为统一后缀改变实现方式。

### 3. 独立流程自成子域，根目录保持克制

子流程拥有独立表单、状态、模型或校验时，必须按实际业务职责建立子目录；不要求同时具备页面、API、store 才允许建立子域。该流程的视图、状态逻辑、模型与校验一起归拢，不能分别遗留在模块公共技术目录或根目录。命名遵循 naming 分册。

模块根目录保留页面入口、路由装配以及多个子域实际共用的 API、类型或配置。其他实现按实际消费者归入所属子域，不能因为文件名带有模块前缀就继续平铺在根目录。

### 4. 拆文件必须同时控制体积与数量

- 新增或本次拆分后的 `.vue` 最多 250 行，其余手写脚本与样式文件最多 300 行；均按物理行统计，包含空行和注释，SFC 统计模板、脚本、样式总和。
- 独立交互区块拆为当前实体的私有组件；状态和副作用放实体 composable；纯转换函数、列定义和字典按各自职责放在实体内。
- 只有多个实体共用的展示结构和样式才提升到父级公共位置；保持原有样式作用域。
- 禁止用 `part1.ts`、`part2.ts` 任意切段，或把整个脚本、模板、样式搬到一个新的超长文件；禁止为压行数合并语句或删除有用注释。
- 拆分后父目录与新子目录均检查容量。只有一个入口、几行配置且没有独立职责的文件，不为凑模板继续碎片化。

### 5. 开发工具与正式集成能力各自归属

存在开发工具时，应与生产业务实现分目录维护；存在正式外部接入能力时，应按用途建立独立的集成边界。文件名和历史位置不能替代用途判断，目录名沿用项目约定。目录隔离之后，还需检查开发路由条件及生产入口是否误引开发代码。

### 6. 子域依赖与交付检查

子域按实际业务名命名。禁止用 `modules/`、`children/`、`sub/` 隐藏具体职责。仅服务于父页面的小表单可放该页面的私有 `components/`；成套流程按上面的业务边界归拢。

子域之间禁止交叉穿透私有实现。共用能力提升到最近共同业务边界；`components/`、`core/` 与 `shared` 均不作为容量超限的中转仓库。

开始新增文件前与交付前，使用 [scripts/check-structure.py](../scripts/check-structure.py) 扫描所属模块。它检查 `.vue`、`.ts`、`.tsx`、`.js`、`.jsx`、`.mjs`、`.cjs`、`.mts`、`.cts`、`.css`、`.scss`、`.sass`、`.less`；测试、Mock、手写声明文件使用相同口径。默认跳过依赖、构建和覆盖率目录；其他明确生成文件可用 `--exclude` 指定相对路径 glob，不得排除手写业务源码。符号链接目录不展开。

扫描器仅检查数量与行数；业务归属、是否把私有文件放进公共池、是否制造无意义分层由 Review 检查。交付时同时给出数量检查结果与本次目标目录树。存量超限的处理方式见 [migration.md](migration.md)。

## 共享接口与共享类型边界

接口和类型应放在 "最近的共同业务边界"：

- 只给一个二级模块用 → 放入当前二级模块内部 `api.ts` / `types.ts`。
- 给同属一个一级模块的多个二级模块共用 → 放入一级模块的 `shared/api/` 或 `shared/types/` 中（例如 system 下共用部门、角色、岗位下拉接口）。
- 跨越多个一级模块且业务语义稳定 → 放入对应的 `src/shared/biz/<domain>/`。
- 仅负责 HTTP、WebSocket、鉴权头等传输机制 → 放入 `src/services/`；具体业务接口不进入 services。
