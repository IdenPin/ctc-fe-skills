# Composable 契约

## 抽取条件

Composable 用于封装响应式状态或副作用。跨组件复用、独立的复杂状态流程、需要集中管理的副作用都可以成为抽取原因；不要求必须复用才允许抽取。少量局部状态与处理函数可以继续放在组件内。

纯转换函数不包装成 `useXxx`。组件拆出 composable 后，接口仍应围绕一个清晰流程，而不是返回原组件的所有变量和方法。

## 输入与依赖

- MUST 区分初始快照与持续响应的输入，并让调用方清楚其更新语义。
- 依赖持续变化的值时，接收 ref、getter 或明确的响应式对象，并在 computed、watch 或副作用执行点读取；不能只在初始化时读取一次。
- 从 props 传入原始值不会自动形成响应式依赖；传入 getter 或 ref，并验证输入改变后的行为。对象解构也不能默认认为会保留响应性，需按实际类型和 Vue 版本处理。
- 外部服务、路由、store 等依赖应在实现或接口中清晰可见；禁止通过任意注入、事件总线或读取其他组件内部字段隐式寻找输入。
- 可复用逻辑避免直接操纵调用方的弹窗或导航，优先返回状态和结果，由拥有页面流程的组件协调。

## 状态与返回值

- MUST 默认实例隔离：局部状态在函数内部创建。确需共享会话或全局状态时，显式设计其生命周期、重置方式与所有者，不能偶然使用模块级 ref 共享。
- SHOULD 返回普通对象中的 refs、computed 和语义明确的动作，支持调用方解构后继续响应式更新；若返回 reactive 对象，明确不能用普通解构取得持续响应的原始值。
- MUST 只暴露调用方确实需要的状态与动作。需要受控修改的状态使用只读接口与动作；确需 `v-model` 的可写状态则明确支持的写入契约。
- 不返回内部 AbortController、完整服务容器或供任意调用的内部辅助函数来代替正式 API。
- 派生值使用 computed。避免多个 watch 在不同方向同步同一状态，或在组件和 composable 中各维护一套同义 loading、选择值和错误。

## 副作用与异步生命周期

- MUST 明确请求在初始化、输入变化还是显式动作时触发，避免组件挂载与 composable 各发起同一请求。
- 输入变化时，使前一任务失效；组件作用域销毁时清理请求、监听器、订阅和定时器。生命周期与清理注册应发生在有效的组件或 effect scope 中。
- 请求完成时检查是否仍属于当前有效操作。不能只取消请求而忽略迟到结果，也不能让旧任务的 finally 清除新任务的 loading。
- 错误、成功、空结果和重试状态由调用方可观察；取消请求不作为普通失败提示，不使用空 catch 隐藏真实失败。
- 支持独立于组件运行的 composable 时，明确提供停止方式；组件内自动清理与外部手动停止的职责不得含糊。

## Review 与验证

按实际行为验证：输入更新是否重新计算或请求、实例是否互相隔离、解构后是否仍更新、重复触发是否受控、卸载后是否清理，以及旧请求是否能覆盖新请求。只对涉及的契约补充必要覆盖，不要求每个简单封装建立一套固定测试模板。
