# 模板与异步交互

## 模板正确性

- MUST 为有状态或可增删、重排的列表使用稳定唯一的基本类型 key；禁止使用随机值或整个对象作为 key。索引仅适用于顺序固定且没有依赖身份的子组件或 DOM 状态的简单展示列表。
- 同一元素不混用 `v-if` 与 `v-for`；先计算过滤结果，或在容器层处理整体显隐。
- MUST 保持渲染过程无副作用：模板、computed、JSX 渲染及单元格渲染函数不发请求、写 storage 或修改响应式状态。用户操作由事件处理器执行。
- 重复筛选、复杂分支和较重计算放在脚本侧的派生值或纯函数，避免每次渲染重复构造无关数据。
- MUST 对外部集合、可空对象和数值建立明确展示规则。`0`、`false`、空字符串、缺失值按契约区分，不能统一通过真值判断替换为占位符。
- 不可信内容以文本展示；确需富文本时采用项目认可的净化策略，不能直接交给 `v-html`。

## 加载、空结果与失败

- MUST 区分尚未请求、正在加载、成功空结果、成功有数据和失败。请求完成前不能把未知结果呈现为“暂无数据”。
- 后续刷新是否保留旧结果由交互需求决定，但旧结果不得伪装为新请求的成功响应。
- MUST 为失败提供合适的反馈和恢复入口；请求完成、异常和取消都应结束所属操作的等待状态。
- 多个独立资源分别管理状态；只让界面等待实际依赖的数据，不因无关媒体或辅助资源失败阻断全部内容。
- 异步组件的模块加载、初始化和渲染失败应有结束等待与恢复策略，不能只依赖子组件挂载后的 finally。

## 表单与写入动作

- MUST 明确草稿的初始化、重置与提交时机。取消、重新打开、切换编辑对象时按设计恢复；避免通过深度 watch 原始对象持续覆盖用户输入。
- 提交前执行必要校验；提交期间阻止重复触发；失败时保留可恢复的输入，不在 finally 中清空草稿或报告成功。
- 校验与请求结果对应触发它的当前上下文。取消或过期结果不能关闭另一个弹窗、清空新表单或更新新对象。
- 写入结果不明确时，按接口的幂等和状态核对约定处理；取消浏览器请求不能视为服务端已撤销操作。
- 请求层和组件明确错误提示的负责方，避免重复弹出同一错误；面向用户显示可理解的信息，不直接展示堆栈、凭证或原始响应对象。

## 错误兜底

沿用项目既有错误处理入口，不为以下通用示例机械新建包装文件。未知异常的转换必须有安全兜底；不在 catch 中无保护地 `JSON.stringify` 未知值，因为循环引用或 BigInt 会使转换再次抛错。

```ts
function toError(value: unknown): Error {
  if (value instanceof Error) return value
  return new Error(typeof value === 'string' && value.trim() ? value : '操作失败，请重试')
}
```

已校验的业务错误可使用明确的错误类型保留提示信息，未知输入按兜底策略处理。

## 基本可访问性

- 触发动作优先使用 button、链接等原生交互元素；自定义交互应提供键盘操作、可感知名称和必要状态。
- 表单标签与输入关联，错误信息能定位到对应字段；不能只通过颜色表达成功或失败。
- 弹层打开后焦点进入合理位置，关闭后按组件库或项目约定恢复；加载或禁用状态不能留下仍可重复触发的隐藏入口。
