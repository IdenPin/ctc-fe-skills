# 生成或调整页面

先读取[统一布局契约](references/layout-contract.md)与[布局变量](assets/layout-tokens.css)。进入 page 模式后，再按所选模板读取[输入 Schema](references/page-spec.schema.json)的相关分支和公共定义。需要示意时查看[HTML 预览](assets/layout-spec.html)；需要完整配置时读取[输入示例](references/page-spec.examples.json)中对应的一项。纯布局任务无需加载完整业务配置。本技能的完整资料位于当前目录，可单独复制使用。

## 确定范围

1. 查看目标项目的入口说明、已有页面、布局外壳、组件和依赖，确认可用高度、技术栈及输出路径。有 CodeGraph 索引时遵循项目的代码定位约定。
2. 把用户需求归一化为 PageSpec。只要布局时使用 `mode: layout`；需要业务页面时使用 `mode: page`，按模板分支确认输入。缺省先推进 layout，不自动增加业务字段、控件或模拟数据。
3. 优先复用现有组件与布局。检查项目依赖：若项目已安装 `@ctc-front/components-ui-next` 且为常规单表报表查询，T01 优先复用组件库现有的 `<CtcReport>`（参照契约中的插槽映射）；若未安装或为解耦/多表场景，可使用内置的标准骨架 [TablePageLayout.vue](templates/TablePageLayout.vue)。没有可复用组件时按本次范围实现骨架，不引用项目中不存在的虚拟组件。

## 实现

- 新 Vue 3 代码默认使用 Composition API 与 `<script setup lang="ts">`，明确 props、emits 和行数据类型，不使用 `any` 掩盖未知数据。入口页面负责组合区域，复用现有组件或拆出有独立职责的区域。
- 目标技术栈默认 Vue 3 + TypeScript + Element Plus。已有项目约定优先；不为了满足技能而切换组件库、安装另一套样式工具。
- 若项目已用 Tailwind 或 UnoCSS，沿用该工具映射布局变量；需要组件内部样式时允许最小范围的 scoped CSS 或现有样式入口。禁止的是无意的全局样式污染。
- 从统一契约读取必需/可选插槽、工作区和白卡分层、四边间距、侧栏宽度及滚动规则。未启用的可选插槽不占位。
- 普通表格与虚拟表格按需求选择；先建立父级高度链，再让表格填满剩余视口。T03（GIS HUD）仅在配置表格面板时应用表格规则。
- 业务数据优先接入已存在的服务；没有后端信息时暴露类型明确的接入面。查询、分页、切换和确认行为按配置启用，不创造 API、业务结论或真实外观的模拟数据。
- 检查输入中各集合 key 唯一、页签默认项有效、引用存在，以及可选区域配置与 `enabledSlots` 的一致性。页面数据源决定字段和交互，模板只约束区域。
- GIS 覆盖层保留地图事件穿透，交互面板恢复事件；实例和副作用清理遵循库与项目实际接口。

## 交付

依据本技能携带的统一契约自查插槽、视觉分层、滚动、按需交互及资源清理。已获授权的本次实现可修复发现的问题。

使用项目现有的类型检查、lint 和适用验证；布局可运行时核对目标 PC 尺寸、空数据、长内容及外围留白。交付时简述采用的模板、模式、接入点、实际检查结果和未验证项，不把未执行的检查报告成通过。

## 维护资料

当前技能目录是完整分发单元。两份技能各自携带同版本规则；修改公共资料后，可用[同步工具](scripts/sync-shared-resources.py)比较或发布到审查技能：在当前技能目录执行 `python3 scripts/sync-shared-resources.py --target ../ctc-fe-code-auditor --check`，确认维护变更后使用 `--apply`。该工具只用于维护副本，日常生成、自查不需要另一个技能目录。
