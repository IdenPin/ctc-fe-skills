# 审查布局和页面

先读取[统一布局契约](references/layout-contract.md)与[布局变量](assets/layout-tokens.css)。审查配置时再读取[输入 Schema](references/page-spec.schema.json)，对照示意时查看[HTML 预览](assets/layout-spec.html)。这是一套审查流程，不是自动注册的静态扫描器或提交门禁。

## 范围与模式

- 确认目标文件/变更范围，以及模板 ID（L01～L08）和 layout/page 模式；可从调用方或文件推断。无法确定时标为待确认，不硬套某一模板。
- 默认 review：读取目标、相关布局外壳和必要的调用方，报告问题，不修改文件。
- 用户已要求修复或在已授权的生成任务内做自查时，可以修复本次范围内的问题；保持现有业务行为，变更后复查受影响部分。

## 检查

1. **视觉与插槽**：对照 L01～L08 契约清单核对区域及可选插槽；业务页面优先通过 `@ctc-front/components-ui-next/layout` 导入布局组件。未启用的可选插槽不应残留空白包装或多余边框。
2. **高度与收缩链**：嵌入宿主基座或页签的页面，**严禁全局 `100vh` 锁死**；检查整个父级高度链是否由父容器 `height: 100%` 驱动，并保持完整的 `min-height: 0; min-width: 0; flex: 1;` 收缩链。独立全屏外壳与浮层按需使用视口策略。
3. **滚动责任人**：确认每个内容区的唯一定义滚动归属：L01 表格负责内部滚动；L02、L03、L05 保持双轨独立滚动；L07 保持全局单根滚动，子卡片严禁局部滚动；L05 在浮层中挂载时外壳必须开启 `content-fill` 并设置 `overflow: hidden; padding: 0;`。杜绝意外的双滚动条或内容裁切。
4. **按需交互**：只审查真实启用的功能。查询/重置是否同步条件和结果；分页是否受控且容量变化会回到第一页；切换后是否有旧选择或异步旧响应污染。真实数据区域应有 loading、空态和错误反馈；layout 模式无需这些业务分支。
5. **GIS/图表与副作用清理**：L04 地图画布必须保留拖拽缩放交互，覆盖层包装 `pointer-events: none`，各功能面板恢复 `pointer-events: auto`。ECharts 与地图实例必须在 `onUnmounted` 中正确释放，断开 `ResizeObserver`，清除计时器与在途请求。
6. **工程与类型**：组件默认 `<script setup lang="ts">`，明确 props 与 emits 类型，严禁 `any` 掩盖未知数据。遵循目标项目已有的依赖与代码定位约定。

## 证据与验证

以当前技能目录为工作目录运行 `python3 scripts/check-package.py`；该命令检查本技能携带资料与 L01～L08 契约的一致性。业务页面运行 `python3 scripts/validate-page.py <Page.vue> --spec <page-spec.json>`；每个浮层或独立布局追加对应的 `--spec`。主页面与各弹层分别选型。核对 L06 是否通过 cards 属性托管跨度和高度，并使用目标项目已有的类型检查、lint、测试及浏览器验证。

按影响排序报告：位置、触发条件、实际后果、建议修复。区分确定的问题、需要运行确认的风险和未验证项；避免把风格偏好当作错误。无问题就直说，保留检查范围和实际验证结果。fix 模式说明修改内容与复查结果；review 模式不直接应用补丁。
