# 审查布局和页面

先读取[统一布局契约](references/layout-contract.md)与[布局变量](assets/layout-tokens.css)。审查配置时再读取[输入 Schema](references/page-spec.schema.json)，对照示意时查看[HTML 预览](assets/layout-spec.html)。这是一套审查流程，不是自动注册的静态扫描器或提交门禁。

## 范围与模式

- 确认目标文件/变更范围，以及模板 ID 和 layout/page 模式；可从调用方或文件推断。无法确定时标为待确认，不硬套某一模板。
- 默认 review：读取目标、相关布局外壳和必要的调用方，报告问题，不修改文件。
- 用户已要求修复或在已授权的生成任务内做自查时，可以修复本次范围内的问题；保持现有业务行为，变更后复查受影响部分。

## 检查

1. **视觉与插槽**：对照契约清单核对区域及可选插槽；不要求页面渲染全部可选功能。T01～T02 检查浅灰蓝工作区、四边外间距、白色内容卡片及白色表格；T01 若直接复用 `<CtcReport>`，核对 `search-bar`、`container-top`、`tool-bar` 插槽映射与 `auto-height` 传参是否合规；T01 确认底栏属于同一白卡。检查布局变量和 4px 间距栅格；边框、字体、内容列宽和文档注释不按间距规则误报。
2. **高度与滚动**：检查整个父级高度链、flex 收缩、`min-height: 0` 和横向 `min-width: 0`。关注页面是否意外溢出、表格是否内部滚动、分页/底栏是否保持可见。有效的动态高度同样合规，不以某个 class 或 `height="100%"` 的字面出现作为通过条件；普通滚动不等于虚拟滚动。
3. **按需交互**：只审查真实启用的功能。查询/重置是否同步条件和结果；分页是否受控且容量变化会回到第一页；切换后是否有旧选择或异步旧响应污染。核对可观察行为，不规定函数名。真实数据区域应有 loading、空态和错误反馈；layout 模式无需这些业务分支。
4. **GIS/图表**：交互面板能接收事件，空白区域保留地图操作；层级不误挡图例和工具。按实际库 API 清理本页拥有的实例、监听器、observer、计时器和请求，不能仅搜索 `dispose()`/`destroy()` 就判定无泄漏。
5. **工程与操作**：检查类型、已存在的引用、组件职责和样式作用域。使用项目现有的确认机制处理破坏性操作，并防重复提交；普通筛选重置无需确认。核对后端接入与错误处理，不允许伪造可用服务。

## 证据与验证

以当前技能目录为工作目录运行 `python3 scripts/check-package.py`；该命令只检查本技能携带资料的一致性，不验证页面运行效果。业务页面使用目标项目已有的类型检查、lint、测试与可行的视觉验证。

按影响排序报告：位置、触发条件、实际后果、建议修复。区分确定的问题、需要运行确认的风险和未验证项；避免把风格偏好当作错误。无问题就直说，保留检查范围和实际验证结果。fix 模式说明修改内容与复查结果；review 模式不直接应用补丁。
